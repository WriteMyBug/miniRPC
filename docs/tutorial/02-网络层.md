## 4. 技术原理

### 4.1 单 Reactor 线程模型

```text
                          EventLoop（一个线程）
        ┌─────────────────────┼──────────────────────┐
   EpollPoller            wakeupChannel          pendingFunctors
   （epoll fd +           （eventfd，跨线程       （其他线程投递的任务）
    fd→Channel map）       唤醒用）
        │
   epoll_wait 返回就绪 Channel 列表
        │
   Channel(listen fd)   Channel(conn1)   Channel(conn2)
        │                    │                │
   TcpServer            TcpConnection     TcpConnection
   （连接表 map）         （input/output Buffer）
```

设计约束：**所有网络对象只允许在 loop 线程操作**（由 `EventLoop::assertInLoopThread` 强制）。网络层因此除任务队列外无锁。业务执行下沉线程池（第 3 章），回包经 `runInLoop` 回到 loop 线程。

### 4.2 事件循环一轮迭代

```text
while (!quit_):
  1. poller_->poll(10000, &activeChannels)   // 最多等 10s
  2. for ch in activeChannels: ch->handleEvent()  // 分发就绪事件
  3. doPendingFunctors()                      // 执行跨线程任务
```

10s 超时的作用：没有网络事件时，主线程也能周期性检查 pending 任务（比如 `quit()` 后的清理）。

### 4.3 Buffer 读写游标模型

```text
┌──────────┬────────────────┬──────────────────┬────────────────┐
│ prepend  │ 已读(可回收)    │ 未读数据(readable) │ 可写空间(writable)│
│ 8 字节    │ readerIndex_    │ reader→writer    │ writer→end      │
└──────────┴────────────────┴──────────────────┴────────────────┘
```

- `retrieve(n)` 只移动 `readerIndex_`，不删除数据（O(1)）；
- `ensureWritableBytes`：可写空间不足时，把未读数据 `std::copy` 到头部 prepend 之后，再扩容；
- `readFd` 用 `readv` 写两处：Buffer 剩余空间 + 64KB 栈上 extrabuf，一次系统调用尽量读尽。

### 4.4 TcpConnection 状态机

```text
Connecting → Connected → Disconnecting → Disconnected
   │            │             │               │
 创建后        connect       shutdown()      handleClose()
              Established   （等输出缓冲      完成后对象由
                            清空再 SHUT_WR）  shared_ptr 释放
```

生命周期由 `shared_ptr` 管理：TcpServer 的 `connections_` map 持有；线程池任务捕获 `TcpConnectionPtr` 可延长生存期；`handleClose` 中 `closeCallback_` 触发 map erase，最后一个引用释放时析构并 close fd。

## 5. 重点实现拆解

### 5.1 EventLoop 构造与唤醒 [src/net/EventLoop.cpp]

构造函数创建 eventfd（`EFD_NONBLOCK|EFD_CLOEXEC`），注册 wakeupChannel 读事件。跨线程投递路径：

```text
线程池线程调用 TcpConnection::send
  → runInLoop（不在 loop 线程）
  → queueInLoop：mutex 保护 push pendingFunctors_
  → wakeup：eventfd 写 1
  → loop 线程 epoll_wait 返回 → handleWakeup 读空 eventfd
  → doPendingFunctors：swap 出队列后执行（避免持锁执行回调）
```

### 5.2 EpollPoller 增删改 [src/net/EpollPoller.cpp:updateChannel]

```cpp
if (channels_.find(fd) == end) {           // 新 fd
  if (channel->isNoneEvent()) return;      // 无事件不 ADD
  update(EPOLL_CTL_ADD, channel);
} else if (channel->isNoneEvent()) {       // 事件清空
  update(EPOLL_CTL_DEL, channel);          // DEL 后不能再 MOD
  channels_.erase(fd);
} else {
  update(EPOLL_CTL_MOD, channel);
}
```

注册时 `event.data.ptr = channel`，就绪时 `static_cast<Channel*>(data.ptr)` 直接还原，O(1) 无查找。

### 5.3 Channel 事件分发 [src/net/Channel.cpp:handleEvent]

```text
EPOLLHUP && !EPOLLIN   → closeCallback    （对端关闭）
EPOLLERR               → errorCallback    （对端 RST，读取 SO_ERROR）
EPOLLIN|PRI|RDHUP      → readCallback
EPOLLOUT               → writeCallback
```

HUP 特判原因：对端 close 时 epoll 同时给 HUP，若不单独处理会误入读回调且连接不回收。

### 5.4 TcpConnection 读写 [src/net/TcpConnection.cpp]

`handleRead`：

```text
readFd 读入 inputBuffer_
  n > 0  → messageCallback（业务入口；echo/RPC 从这里进入）
  n == 0 → handleClose（对端关闭）
  n < 0  → EAGAIN 直接返回；其他 errno 记日志并关闭
```

`sendInLoop` 快速路径：

```cpp
if (!channel_->isWriting() && outputBuffer_.readableBytes() == 0) {
  nwritten = write(fd, data, len);
  if (nwritten == len) { writeCompleteCallback_; return; }  // 一次写完
  // 否则剩余部分进 outputBuffer_ 并 enableWriting()
}
```

`handleWrite` 持续清空 `outputBuffer_`，写空后 `disableWriting()` 关闭 EPOLLOUT，避免忙轮询。

### 5.5 TcpServer 连接管理 [src/net/TcpServer.cpp]

- `start()`：`signal(SIGPIPE, SIG_IGN)` → bind → listen → 注册 acceptChannel 读事件。SIGPIPE 处理是必须的：向已关闭连接 write 默认终止进程，忽略后 write 返回 EPIPE，错误路径可见。
- `handleNewConnection`：accept 循环直到 EAGAIN；每个连接创建 `shared_ptr<TcpConnection>` 存入 `connections_`，设置 closeCallback 为 `removeConnection`（跨线程安全，内部 runInLoop）。
- `removeConnectionInLoop`：`connections_.erase(name)` 后 `connectDestroyed()`；若线程池任务仍持有连接，对象等任务结束才析构。

### 实验 1：echo 全链路


### 实验 3：破坏性——改 poll 超时

把 [src/net/EventLoop.cpp:loop] 的 `10000` 改为 `100`，重编译跑 echo，用 `top` 观察进程 CPU 升高（每 100ms 空轮询一次）；恢复原值。验证"超时是周期性检查的代价"。

### 实验 4：gdb 验证线程归属（可选）

```bash
gdb --args ./build/examples/echo_server 8888
break src/net/TcpConnection.cpp:handleRead
run
# 另一终端发一条 echo；gdb 中断后 bt，确认调用栈从 EventLoop::loop 进入
```

预期：调用栈顶部为 `EventLoop::loop` → `Channel::handleEvent` → `TcpConnection::handleRead`，验证"拆包在 loop 线程"。

## 7. 面试追问

1. 单 Reactor 为什么一个线程能管理大量连接？（答：IO 多路复用，线程只做事件分发不阻塞在单个 fd 上）
2. LT 与 ET 区别？本项目为何先选 LT？（答：LT 有数据就报；ET 只在状态变化时报、需读到 EAGAIN；LT 实现简单可靠）
3. Buffer retrieve 为什么不删数据？（答：O(1) 游标移动，避免频繁 memmove；空间不足时才搬移）
4. 连接关闭后线程池还想回包怎么办？（答：send 捕获 weak_ptr，runInLoop 投递；loop 线程确认连接存在才写）
5. SIGPIPE 为什么必须忽略？（答：写已关闭连接默认杀进程，忽略后 write 返回 EPIPE 由业务处理）
