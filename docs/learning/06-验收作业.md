# 学习成果验收作业

> 全部必做项通过 = 本学习计划完成。每个作业都标注了"验收标准"，自己判断不达标就回到对应模块文档复习。
> 预计总耗时约 6 小时（已含在 20 小时计划内）。

## 作业 1：全链路讲解（必做，1.5h）

**任务**：不看代码，画一张"一次 Calculator 调用"的时序图，并录一段 5 分钟讲解（或写 500 字讲解稿）。

**必须覆盖的点**：

- 客户端 Stub 调用 → RpcChannel 组装信封和协议头；
- 服务端收包 → Codec 拆包 → 线程池提交；
- 反射查注册表 → 反序列化 → CallMethod → 序列化回包；
- 客户端 seq 匹配 → 填充结果/错误；
- 每个环节说出对应的文件路径。

**验收标准**：能不看资料讲满 5 分钟，中间没有超过 10 秒的卡顿；图里每一条箭头都能说清"谁调用谁、传什么"。

## 作业 2：给 Calculator 加新方法 Pow（必做，1.5h）

**任务**：在 `proto/calculator.proto` 加 `rpc Pow(CalcRequest) returns (CalcResponse)`，在 `examples/rpc/calculator_server.cpp` 的 `CalculatorServiceImpl` 里实现（a 的 b 次方，b 为整数，用 `std::pow`），并在 `calculator_client.cpp` 里调用验证。

**验收标准**：

- 改 proto 后 `cmake --build build -j` 自动重新生成代码，编译通过；
- 客户端 `2^10 == 1024` 输出正确；
- 能回答："为什么加一个方法不用改 RpcServer/RpcChannel 框架代码？"（提示：注册表 + 反射）。

## 作业 3：Buffer 扩展（必做 30min / 选做升级）

**任务**：给 `Buffer` 加 `int32_t peekInt32()`（返回前 4 字节大端整数但不消费），在 `tests/buffer_test.cpp` 加断言。

**验收标准**：`./build/tests/buffer_test` 通过，新增断言真实覆盖"只看不取"。

选做升级：加 `ssize_t readAll(int fd)`（读到 EAGAIN 为止）并配套测试。

## 作业 4：故障剔除实验（必做，1h）

**任务**：按 README"注册中心与负载均衡示例"起 注册中心 + 两个 rpc_node + lb_client。

**步骤与记录**：

```bash
# 终端1
./build/registry/registry_server 18800
# 终端2/3
./build/examples/rpc_node 9001 node-a 18800 500
./build/examples/rpc_node 9002 node-b 18800 500
# 终端4（先看两节点，再杀掉 node-b 等 6 秒再看）
./build/examples/lb_client 18800 20 rr
```

**验收标准**：记录并解释三条日志/输出：

1. 初始 rr 调用两节点计数接近（轮询均匀）；
2. 注册中心出现 `evict stale node ... :9002`；
3. 杀 node-b 后 lb_client 只剩 node-a 且 0 失败；
4. 能口头回答"为什么心跳停止 ≠ 进程消失，注册中心却认为它死了"。

## 作业 5：压测复跑与解释（必做，1h）

**任务**：Release 构建后复跑压测，并写出对三个数字的解释。

```bash
cmake -B build-rel -DCMAKE_BUILD_TYPE=Release && cmake --build build-rel -j
./build-rel/examples/calculator_server 8888 standalone 4 &
./build-rel/benchmark/benchmark 127.0.0.1 8888 1 1000
./build-rel/benchmark/benchmark 127.0.0.1 8888 40 500
./build-rel/benchmark/benchmark 127.0.0.1 8888 200 100
```

**验收标准**：能解释这三个现象（对得上 [../interview-qa.md](../interview-qa.md) 第 7 节即可，但要用自己的话）：

1. 为什么 40 并发附近 QPS 最高（~3 万），200 并发反而略降？
2. 为什么服务端 4 线程优于 8/16 线程？
3. 为什么服务端 CPU 只有约 1.3 核，瓶颈却在单 Reactor？

## 作业 6：模拟面试（必做，1h）

**任务**：

1. 对着 [docs/interview-qa.md](../interview-qa.md) 的 30+ 个问题逐个自答（每个先答 30 秒，再看答案）；
2. 找一位同学/朋友模拟面试官，从下面 8 个问题里随机抽 5 个问自己；
3. 现场改一个代码：在面试官面前把作业 2 的 Pow 删掉重写一遍（计时 10 分钟）。

**抽问题池**：

1. 为什么用 epoll 而不是每连接一线程？
2. 粘包/半包怎么解决？
3. 服务端怎么做到加服务不改框架？
4. 超时重试为什么换新 seq？服务端重复执行怎么办？
5. 线程池为什么 4 线程最优？
6. 心跳超时设多长？为什么？
7. 一致性哈希为什么用虚拟节点？节点挂了影响哪些请求？
8. 压测数字里 P99 为什么在高并发下变大？

**验收标准**：5 题中至少 4 题能在 1 分钟内给出有条理的回答；现场改代码 10 分钟内编译运行通过。
