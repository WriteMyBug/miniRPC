# 简历项目描述（MiniRPC）

> 使用说明：这是为"校招 C++/后端"准备的简历项目条目。写简历的原则是**数字真实、范围诚实、深度可见**——
> 面试官会顺着你写的每一个词追问，宁可写"同步客户端"也不要写"高性能异步"，宁可写"约 5000 行"也不要写"3 万行"。

## 1. 一句话版本（自我介绍的锚点）

> 基于 epoll + 线程池 + Protobuf 自研的一个约 5000 行 C++17 轻量 RPC 框架，实现了从 TCP 传输、协议编解码到注册中心与负载均衡的完整调用链。

## 3. 详细版（可放在"项目经历"展开，或作为面试前复习提纲）

```text
MiniRPC —— 轻量级 C++17 RPC 框架（2026.07 - 2026.08，个人项目）

目标：以校招面试为导向，从零实现一个可讲清"一次远程调用全链路"的 RPC 框架。

主要内容：
1. 网络层：基于 epoll 的单 Reactor 事件循环（EventLoop/EpollPoller/Channel），
   主线程负责 IO 分发，业务下沉线程池；Buffer 用读写游标 + readv 处理粘包半包；
   eventfd 实现跨线程唤醒与任务投递。
2. 协议与编解码：自定义 24 字节协议头（魔数/版本/类型/序列号/长度），
   大端编码，Codec 支持半包不消费、粘包循环解析，并对非法报文做长度防御。
3. RPC 核心：Service 注册表 + protobuf 反射实现通用方法分发（新增服务不改框架）；
   同步客户端通道按 seq 匹配响应，超时换新 seq 重试，服务端业务错误不重试。
4. 服务治理：注册中心（注册/发现/心跳剔除）本身是一个 RPC 服务；
   客户端负载均衡支持轮询与一致性哈希（虚拟节点），连接级失败自动换节点重试。
5. 工程化：6 个测试目标（单元 + 集成），自研压测程序输出 QPS/P99/服务端 CPU/内存；
   压测结论：40 并发约 3.1 万 QPS、P99 2.6ms，服务端 CPU 约 1.3 核，
   瓶颈在单 Reactor 串行处理路径（已分析后续多 Reactor 优化方向）。
```

## 5. 写作禁忌（应届生人设保护）

- ❌ 不要写"高并发""高性能分布式""支持大规模集群"——本项目单 Reactor、同步客户端，数字只有 3 万 QPS 级别；
- ❌ 不要写"实现一致性协议/分布式事务"——计划书明确列为非目标；
- ❌ 不要写"异步客户端"——还没做；
- ❌ 不要写"多线程 epoll"——实际是单 Reactor + 线程池，措辞要准确；
- ✅ 可以主动说"学习型项目，规模控制在 5000 行，每个模块都能讲半小时"——应届生的合理定位。
